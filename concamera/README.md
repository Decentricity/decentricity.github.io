# ConCamera

ConCamera is a test-in-production fork of QuasiCamera.

It is a real camera whose photographs are regenerated by an image model. The source photograph supplies visible human likenesses and camera viewpoint; the generated result may reinvent the setting, objects, clothing, weather treatment, and photographic surface.

ConCamera keeps the QuasiCamera face-preservation pipeline, then replaces the separate remote object-analysis request with a local browser CNN pipeline. Object recognition runs on the captured still inside the browser and returns the same semantic object/relationship metadata consumed by the prompt builder and JSON export.

## Local Vision Runtime

ConCamera uses transfer learning with compact pretrained models:

- Detector: TensorFlow.js COCO-SSD `lite_mobilenet_v2`
- Optional crop classifier: TensorFlow.js MobileNet v1 `alpha: 0.25`
- Runtime: TensorFlow.js 4.22.0, preferring WebGL, then WASM/CPU fallback where available
- Detector confidence threshold: `0.45`
- Analysis image maximum dimension: `640px`

Approximate first-load model/runtime download is roughly 8-12 MB compressed. Models are lazy-loaded and cached by the ConCamera service worker model cache when browser CORS/cache behavior permits it.

## What Happens On Shutter

1. The app freezes camera pose, manual settings, indoor/outdoor mode, time, GPS, weather, and other context.
2. It captures a real still image from the device camera.
3. It creates a developing film placeholder immediately.
4. A bounded queue analyzes the still image for visible faces.
5. The subject mode determines which detected faces should be preserved.
6. A local CNN object analyzer detects salient non-human objects, optionally classifies selected crops, normalizes labels, and derives geometric object relationships.
7. The hidden prompt receives selected face references, local object semantics, object relationships, camera pose, context, and manual settings.
8. In `GROUNDED` mode, the original source image is sent to the final image-generation provider. In `FREE` mode, the source image is omitted and only face crops plus structured prompt context are sent.
9. The generated image replaces the placeholder and is stored in the film roll.

## Subject Modes

- `LANDSCAPE`: preserve no face if none are detected; otherwise incorporate one selected face indirectly into the environment as a mural, poster, textile, reflection, relief, or similar non-grotesque element.
- `PERSON`: preserve exactly one selected source face as the main subject.
- `GROUP`: preserve multiple selected source faces as the principal group, up to the MVP reference limit.
- `CROWD`: preserve selected source people once each among additional synthetic people.

Selection is deterministic for a capture job, favoring larger, more centered, more usable faces while retaining a seeded pseudo-random component.

## Privacy

The original source photograph is kept in memory only while a capture job is being processed. It is not added to the gallery, not exported in JSON, and not written to IndexedDB or localStorage by default.

The source photograph is not transmitted for object analysis. Object recognition runs locally in the browser.

For final image generation, `GROUNDED` mode transmits the source photograph and selected face crops to the configured image provider. `FREE` mode omits the source photograph and transmits selected face crops only when faces are selected. Generated images and non-image metadata, including detected/selected face counts, selection strategy, local object concepts, object relationships, and local inference timing, are stored in the film roll.

ConCamera does not perform identity recognition, demographic classification, or biometric embedding storage.

## Provider Configuration

ConCamera uses its own localStorage keys:

```js
localStorage.setItem("concamera.provider", "openai");
localStorage.setItem("concamera.openai.key", "sk-...");
localStorage.setItem("concamera.openai.model", "gpt-image-1.5");
```

Custom endpoints can be configured independently:

```js
localStorage.setItem("concamera.provider", "endpoint");
localStorage.setItem("concamera.endpoint.url", "https://example.com/con-camera-edit");
localStorage.setItem("concamera.endpoint.headers", JSON.stringify({ "Authorization": "Bearer ..." }));
```

OpenAI requests use the image-edit endpoint with JSON image references, selected source/face data URLs, and `input_fidelity: "high"` when a captured source image is present.

## Storage And PWA Isolation

ConCamera has its own:

- IndexedDB database: `con-camera-db`
- frame metadata fallback key: `concamera.frames.v1`
- manual settings key: `concamera.manualSettings.v1`
- OpenAI key/model keys
- manifest name and scope
- service-worker app-shell cache: `con-camera-static-v1`
- service-worker model cache: `con-camera-models-v1`

This keeps it separate from `/anticamera/` and `/quasicamera/`.
