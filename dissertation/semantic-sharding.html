Idea 004 · Decentralized AI · Privacy-preserving inference

ONE QUESTION.
MANY SHARDS.

Semantic Sharding for Privacy-Preserving Decentralized AI: can a private query be decomposed into independently answerable fragments, distributed across ordinary GPU contributors, and reconstructed locally—without any one inference provider seeing the original question?

Research feasibility · preliminary estimates

Compute & corpus requirements

Corpus: Start with 500–2,000 compositional, multi-part prompts with human-reviewed reference answers and annotated sensitive facts; expand to 5,000–20,000 queries for privacy/utility studies. Include deliberately non-decomposable questions and adversarially identifying combinations. Public benchmarks may supply question types but will need privacy-specific annotations.

Compute: One local small instruction model for routing and recombination (illustrative 3B–8B quantized, approximately 2–8 GB weight storage depending on quantization) plus 2–4 simulated remote inference endpoints. The remote models can be ordinary Qwen-class models, including 7B–14B quantized variants; GPU requirements depend on context, concurrency and quantization. A 12 GB consumer GPU is a plausible pilot target for sequential small-model runs, not a promise of simultaneous hosting.

Budget: Pilot: approximately 1,000 prompts × (1 local decomposition + 3 remote shards + 1 local synthesis) ≈ 5,000 model calls, plus adversarial reconstruction runs. Illustrative 20–100 GPU-hours for an initial small-model benchmark is a low-confidence planning range, not measured throughput; log actual tokens, latency, VRAM, network bytes and costs.

Research hypothesis: Privacy-optimized semantic sharding can reduce what any individual untrusted GPU provider learns about a user's complete query while preserving useful answer quality and retaining ordinary, non-cryptographic LLM inference.

Why decentralized AI needs this

Decentralized inference networks could let individuals contribute idle GPUs in exchange for compensation, credits, or access to network inference. Yet a volunteer GPU operator serving an ordinary prompt may be able to read it in plaintext. Transport encryption alone does not solve this; full homomorphic inference and secure multiparty computation can impose substantial computational or communication overhead. This proposal explores a different, explicitly non-cryptographic privacy–utility trade-off: distribute only bounded, semantically useful fragments rather than the complete user query.

Proposed architecture

01 / User device

Private semantic router

A small local model receives the complete prompt, removes or substitutes direct identifiers, decomposes it into subquestions, and keeps the original query and reconstruction plan locally.

02 / Network

Independent GPU contributors

Each untrusted inference provider receives only an assigned shard and runs an ordinary open-weight LLM. No FHE-specific transformer is required. Providers may earn credits or access by contributing compute; incentive design is an optional systems extension, not a privacy guarantee.

03 / Local synthesis

Reassemble the answer

The user's local model combines shard responses using private context, checks consistency, restores authorized personal details and produces a coherent answer.

04 / Threat model

Assume curious operators

Measure what a provider can infer from its shard, metadata and repeated requests. Test collusion, linked queries and adversarial reconstruction. The network must not claim cryptographic secrecy or guaranteed anonymity.

Core research questions

  1. Semantic independence: Which prompts can be decomposed into useful shards without revealing the full original intent to an individual provider?
  2. Privacy leakage: How well can an adversarial LLM reconstruct the original prompt, sensitive attributes, or user identity from one shard or several colluding shards?
  3. Reconstruction fidelity: How closely does local synthesis match the quality, completeness and factual accuracy of direct inference on the original query?
  4. Adaptive routing: Can a local router optimize shard boundaries, provider allocation and optional withholding of sensitive subproblems for privacy, accuracy and cost?
  5. Decentralized feasibility: How do latency, bandwidth, churn, heterogeneous GPUs, provider reputation and collusion affect real-world viability?

Experimental plan

Implement a local router, a simulated pool of 2–4 independent inference providers, a local synthesis stage and an adversarial reconstruction evaluator. Compare direct single-provider inference, simple PII redaction, random splitting, ordinary semantic decomposition and privacy-optimized semantic sharding. Report exact threat assumptions and whether operators can see task metadata, client identifiers or multiple shards.

Measure answer quality with task-specific reference judgments and blinded human evaluation; privacy with sensitive-attribute inference, original-query reconstruction success and attack-model confidence; systems performance with end-to-end latency, token count, GPU-seconds, network traffic and cost. Stratify by compositional versus intrinsically indivisible queries. Include a refusal/local-only path when no privacy-preserving decomposition is feasible.

What would falsify the hypothesis?

If useful shards routinely expose the user's sensitive intent, if colluding providers easily reconstruct the original query, or if local synthesis loses too much accuracy compared with direct inference, semantic sharding may be unsuitable for high-privacy workloads. A successful result is a quantified privacy–utility frontier, not a blanket promise of secrecy.

Prior art and implementation starting points

Related work includes federated and split learning, privacy-preserving prompt rewriting, multi-agent task decomposition, mix networks and cryptographic private inference. None should be conflated with this proposal's specific combination; novelty requires a systematic literature review. Concrete open-source components include Qwen models[1], llama.cpp[2], vLLM[3], and Microsoft Presidio for a redaction baseline[4]. Benchmark candidates include HotpotQA for multi-hop question answering[5] and BIG-bench Hard for difficult reasoning tasks[6]; neither is a ready-made privacy benchmark.

First milestone

On one workstation, emulate three providers with isolated request logs, run 100 annotated prompts, compare direct inference against sharded inference, then give a separate adversarial model each provider's log and ask it to reconstruct private information. Measure privacy leakage, answer quality and total inference cost before adding actual remote GPUs or token incentives.

The bigger question: Can anyone contribute a GPU to an open AI network without becoming an accidental witness to someone else's private conversation?
