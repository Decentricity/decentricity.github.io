# QuasiCamera

QuasiCamera is a separate MVP fork of Anti-Camera.

It is a real camera whose photographs are regenerated by an image model. The source photograph supplies visible human likenesses and camera viewpoint; the generated result may reinvent the setting, objects, clothing, weather treatment, and photographic surface.

For this MVP, QuasiCamera preserves people only. It does not attempt to preserve furniture, buildings, vehicles, pets, signage, or other objects.

## What Happens On Shutter

1. The app freezes camera pose, manual settings, indoor/outdoor mode, time, GPS, weather, and other context.
2. It captures a real still image from the device camera.
3. It creates a developing film placeholder immediately.
4. A bounded queue analyzes the still image for visible faces.
5. The subject mode determines which detected faces should be preserved.
6. Selected face crops plus the source image and hidden transformation prompt are sent to the configured image-edit provider.
7. The generated image replaces the placeholder and is stored in the film roll.

## Subject Modes

- `LANDSCAPE`: preserve no face if none are detected; otherwise incorporate one selected face indirectly into the environment as a mural, poster, textile, reflection, relief, or similar non-grotesque element.
- `PERSON`: preserve exactly one selected source face as the main subject.
- `GROUP`: preserve multiple selected source faces as the principal group, up to the MVP reference limit.
- `CROWD`: preserve selected source people once each among additional synthetic people.

Selection is deterministic for a capture job, favoring larger, more centered, more usable faces while retaining a seeded pseudo-random component.

## Privacy

The original source photograph is kept in memory only while a capture job is being processed. It is not added to the gallery, not exported in JSON, and not written to IndexedDB or localStorage by default.

The source photograph and selected face crops are transmitted to the configured image provider for transformation. Generated images and non-image metadata, including detected/selected face counts and selection strategy, are stored in the film roll.

QuasiCamera does not perform identity recognition, demographic classification, or biometric embedding storage.

## Provider Configuration

QuasiCamera uses its own localStorage keys:

```js
localStorage.setItem("quasicamera.provider", "openai");
localStorage.setItem("quasicamera.openai.key", "sk-...");
localStorage.setItem("quasicamera.openai.model", "gpt-image-1.5");
```

Custom endpoints can be configured independently:

```js
localStorage.setItem("quasicamera.provider", "endpoint");
localStorage.setItem("quasicamera.endpoint.url", "https://example.com/quasi-camera-edit");
localStorage.setItem("quasicamera.endpoint.headers", JSON.stringify({ "Authorization": "Bearer ..." }));
```

OpenAI requests use the image-edit endpoint with JSON image references, selected source/face data URLs, and `input_fidelity: "high"` when a captured source image is present.

## Storage And PWA Isolation

QuasiCamera has its own:

- IndexedDB database: `quasi-camera-db`
- frame metadata fallback key: `quasicamera.frames.v1`
- manual settings key: `quasicamera.manualSettings.v1`
- OpenAI key/model keys
- manifest name and scope
- service-worker cache: `quasi-camera-static-v1`

This keeps it separate from `/anticamera/`.
