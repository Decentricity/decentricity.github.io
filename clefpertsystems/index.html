01 / Where the idea came from

Why I’m revisiting my old expert system

In 2007–2008, I built an expert system for assessing the environmental impacts of cement production using the Warner–Preston method. Years later, looking at decision models like Jev and Clef, I started comparing them with the systems I used to build.

The connection is practical: an expert system already knows how to decide within a defined domain. Run it across many valid input combinations and you have a corpus of cases paired with decisions, without manually labeling every case.

I think of this as transmutation: taking knowledge expressed as symbolic logic and using its outputs to train a neural decision model. The question is whether the model can reproduce those decisions on cases it hasn’t seen. This project builds the pipeline and keeps the Prolog system available to check the answer.

05 / Beyond one knowledge base

Applying this to other expert systems

Many organizations have already encoded specialist knowledge in rules. If this works, those systems could supply training corpora for new decision models, using expertise they already have.

01 / EXISTING EXPERTISE

Reuse the knowledge in the rules

Writing and validating domain rules takes time. An executable rule base provides a starting point for labeled examples when an organization has little historical training data.

02 / CASE GENERATION

Cover cases beyond the archive

The system can label valid scenarios that never appeared in its usage logs. The generator can include rare rule paths and cases near decision thresholds.

03 / EVALUATION

Keep a reference for every version

When the rules change, regenerate the examples and test the model again. Agreement with the source system is measurable; it doesn’t have to be taken on trust.
