# Audit batch 05 — serious organization-backed projects

This batch prioritizes organization-owned repositories because those are the most likely to represent substantial multi-repo research/product work that the old 18-record graph missed.

## Agent1c

### `agent1c-ai/agent1c-ai.github.io` — PUBLIC — first-class project / cloud product
README describes **Agent1c.ai** as a hosted Agentic OS built on HedgeyOS: a web desktop with draggable windows, persistent Hitomi assistant persona, cloud-authenticated chat runtime, Supabase auth, managed xAI path, per-user quota/credits, editable SOUL/TOOLS/heartbeat docs, event-driven agent runtime, relay/browser surfaces, and explicit cloud-vs-local architecture boundaries. This is a major first-class project, not merely “HedgeyOS with chat.”

### `agent1c-me/agent1c-me.github.io` — PUBLIC — first-class sibling product
README describes **Agent1c.me** as a serverless/local-first AI-enabled browser OS built on HedgeyOS. It runs entirely in-browser, BYOK across OpenAI/Anthropic/xAI/z.ai, encrypted in-browser vault, direct provider calls, local threaded memory, heartbeat/Telegram loops, Shell Relay + Tor Relay, Hedgey Browser routing, and no backend for MVP. It explicitly states that Agent1c.me and HedgeyOS are both by Decentricity.

Public normalization recommendation: represent **Agent1c** as one major project with two product modes/surfaces — `agent1c.ai` managed cloud and `agent1c.me` sovereign/BYOK local-first — while preserving that they are separate deployed codebases.

## Keelbase

### `keelbase/keelbase-landing` — PUBLIC — supporting/product landing repo
README says it is the public Keelbase landing/waitlist page, built with Next.js 14, Tailwind, Resend and Notion. Supporting web/marketing surface, not the core system.

### `keelbase/keelbase.github.io` — PUBLIC — first-class serious platform/research prototype
README documents the Keelbase web layer and a five-document architecture/spec set. The target system is a protocol-enforced platform for AI-native businesses on NEAR, with sovereign `Vessel` units, coordination/governance contracts, stateless CEO orchestrators reconstructed from on-chain state + agent docs, scoped specialists/temp agents, persistent Liaison interface, Architect provisioning, TEE inference boundary, NEAR Intents, Four-File Agent Standard, manifest-first/tiered context loading, plan-then-execute anchor semantics, state-transition constraints, counterparty gates, template/bespoke modes, and human+agent web surfaces.

The README is unusually explicit about **vision vs prototype reality**. Current implementation is an internal-alpha browser desktop shell with wallet onboarding, vessel registration, state/proposal views, role-routed chat, backend `/api/overview` + `/api/chat`, and early on-chain anchoring; many target semantics remain incomplete. Public copy must preserve this distinction rather than portraying the full target architecture as already shipped.

Classification: serious first-class project, likely under machine minds/agents + decentralized systems rather than a small web demo.

## NFT Massacre

### `nftmassacre/nftmassacre.github.io` — PUBLIC — first-class game/project
README describes NFT Massacre as a wallet-powered Three.js browser game where NFTs from Ethereum/Solana wallets become interactive NPCs in a 3D arena. Existing prototype includes first-person 3D world, wallet asset ingestion, multichain wallet support, NFT-based NPC spawning, combat/panic interactions and wallet inspection. Its GameFi thesis is that wallet inventory itself becomes game content/state.

### `nftmassacre/nftmassacre-android` — PUBLIC — Android platform component
README describes the native Android WebView wrapper around the NFT Massacre game. Boot-critical game runtime/assets are packaged locally in the APK; wallet/NFT lookup and external browsing remain networked. Includes touch controls, in-world browser bridge, file chooser/download handoff and release packaging.

Normalize as one **NFT Massacre** project with Web + Android surfaces.

## Intent Computer

### `intentcomputer/intentcomputer.github.io` — PUBLIC — first-class project/site evidence
README itself is minimal, so `index.html` was inspected. The site describes **Intent Computer** as a small Linux computer built around a voice-operated command line. User starts with the desired job; the system derives commands/tools, shows the plan, and requires approval before sensitive actions. A lightweight CLI is the default state and graphical apps appear only when useful.

The site also describes **Intent Computer Mini** as pocket-sized intent hardware that pairs over Bluetooth and appears as a normal keyboard/mouse to controlled devices. It handles voice input/provider credentials, shows transcript/proposed commands, and only sends ordinary input events after approval. The site explicitly traces its roots through Agent1c, Hitomi and Dissenter.

This is strong evidence for Intent Computer as a first-class hardware/software project family, not merely the private `intent-computer-mini` repo.

## Simpletext Solana

### `simpletext-solana/simpletext-solana.github.io` — PUBLIC — first-class project
README describes a static browser-hosted **Simpletext** editor with local document storage/import/export plus Solana authorship proofs. A connected wallet can sign the current document; exported metadata stores wallet public key, timestamp, canonical message, content SHA-256 and signature. “Proof of Paste” separately requires wallet-signed provenance events for external clipboard paste and maintains a chained event history; malformed/interrupted chains disable future external paste for the document.

This is substantive authored provenance/editor work and should be represented as a first-class decentralized/document-integrity project, not omitted.
